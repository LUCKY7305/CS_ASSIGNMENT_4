2. THE VULNERABLE CODE PATH & ROOT CAUSE ANALYSIS
--------------------------------------------------------------------------------
Vulnerable Code Path:
File: src/views/vulnerableView.js (Lines 44-58) and src/routes/labRoutes.js (Line 28)

In src/routes/labRoutes.js:
  router.get('/vulnerable', (req, res) => {
    let query = req.query.q;
    if (typeof query !== 'string') query = '';
    const results = query.trim().length > 0 ? searchArticles(query) : [];
    res.send(renderVulnerableView(query, results, mockArticles));
  });

In src/views/vulnerableView.js:
  const reflectionHtml = isSearchPerformed
    ? `
      <section class="reflection-card vulnerable">
        <div class="reflection-target-box">
          Query reflected in HTML response: <strong>${query}</strong>
        </div>
      </section>
    `
    : '';

Why is this vulnerable?
1. The server reads the user-supplied query string from HTTP GET parameter `q`.
2. The server directly concatenates this untrusted value into the HTML response body
   using JavaScript template interpolation (${query}) WITHOUT applying output encoding
   (such as HTML entity encoding: & -> &amp;, < -> &lt;, > -> &gt;, etc.).
3. When the victim's browser receives and tokenizes the HTTP response stream:
   - Encountering `<script>` causes the browser HTML parser to switch from
     Character Data State to Script Data State.
   - The browser cannot distinguish between application-intended HTML markup and
     untrusted user-injected markup.
   - The browser immediately instantiates and executes the script within the origin's
     security context.
